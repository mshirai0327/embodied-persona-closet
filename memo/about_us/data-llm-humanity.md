## 成果物

### このPJは `wardrobe` と何が違うの？

`embodied-claude-wardrobe` は、もともとかなり強い基盤を持っています。

- `SOUL.md` を中心にした人格の土台
- `memory-mcp` と `FLASH.md` による記憶
- `interoception` による身体感覚の注入
- `autonomous-action.sh` による heartbeat 型の自律行動
- カメラ、音声、温度、移動などの実機接続

このプロジェクトは、そこに Reflecta 由来の「人格データを層に分けて管理する」という考え方を重ねています。

要するに、

- `wardrobe` は身体と生活の基盤
- このPJは、その上に人格データの整理と運用ルールを足したもの

です。

ただの設定変更版ではなく、

- 変わらないものは変わらない
- 成長するものは履歴を持って変わる
- 気分や体調はその時々で揺れる
- 直近の文脈は流れたり、思い出されたりする

というレイヤを意識して、人間味を支えるデータ構造を入れようとしています。

### 生体データのレベル分け

このプロジェクトでは、人間らしさに関わるデータを大きく 4 層で考えています。

#### Lv1 不変の核

原則として変わらない、同一性の中心です。

- 例: 誕生日、性別、クロノタイプ、苦味感受性、知能、根源的な性格傾向
- 現在: `SOUL.md` と `BODY.md` に分散して保持

毎回の会話で都合よく変わらないことが重要です。ここが揺れると、人間味より先に不気味さが出ます。

#### Lv2 不可逆的な成長

時間をかけて変化し、簡単には戻らないものです。

- 例: 身長、骨密度、握力、声の高さ、視力、聴力
- 現在: `BODY.md` で履歴つき管理

これは「成長した痕跡」を持つための層です。

#### Lv3 可変的な状態

日常の中で頻繁に変わる状態です。ここはさらに 2 つに分かれます。

##### Lv3-1 バイタル

生物的な可変データです。

- 例: 体重、体脂肪率、体温、血糖値、血圧、睡眠時間、睡眠質
- 現在: `STATUS.md` に一部だけ実装

現状では、

- 体重は保持
- 体温、睡眠時間、睡眠質は項目あり
- 体脂肪率、血糖値、血圧は未実装

という段階です。ここは今後、センサーや推定ロジックで埋めていきたい層です。

##### Lv3-2 情緒・関係性

気分や活力、関係性のように、日々の経験で動く状態です。

- 例: mood、energy、health、trust、satiation
- 現在: `STATUS.md` で運用中

heartbeat のたびに更新され、すでに行動選択にも使われています。

#### Lv4 フラジャイルな文脈

数値化しきれない、そのときどきの文脈です。

- 例: その日の気分、最近の興味、会話の余韻、進行中のテーマ
- 現在: `memory-mcp`、`state.md`、会話履歴、`memo/` 群で保持

ここは固定データではなく、「思い出される」「流れていく」こと自体が重要です。

### それらのデータをどう使うの？

このPJでは、データは保存するだけでは意味がありません。行動や推論に効いて、はじめて人格になります。

#### 1. Lv1 と Lv2 は、存在の連続性を守る

- セッションをまたいでも設定がぶれない
- 成長の履歴を持てる
- 会話のたびに別人にならない

という役割です。

#### 2. Lv3 は、今の状態を行動へ反映する

`STATUS.md` の数値は、単なる飾りではありません。

現在は主に、

- `interoception` が数値状態を身体感覚の文に変換する
- `status-hint` が行動優先度に変換する
- heartbeat がその回の自律行動へ反映する

という使い方をしています。

つまり、「疲れているから軽い作業を選ぶ」「満ちているから整理に向かう」のように、状態が行動へつながる設計です。

#### 3. Lv4 は、短期的な文脈と記憶の橋渡しをする

`memory-mcp` や `state.md` は、直近の流れを保つために使われます。

- 何をしていたか
- 何が気になっていたか
- どんな会話が続いていたか

を保持し、必要に応じて思い出させます。

#### 4. `SYSTEM.md` は身体そのものではなく、身体の条件を与える

このPJでは、生体データとマシン設定を分けています。

- `BODY.md` は人格の身体
- `SYSTEM.md` は今どんな機械と声で動いているか

という分担です。
まず前提として、Embodied-AI （身体性を持ったAI）というとき、その「身体」とは、AIの肉体＝ロボット（familliar-aiなどでいう、PZTカメラやロボット掃除機など）を指すかと思います
このプロジェクトでは、**身体＝人間としての肉体**を意味します


### データ間因果グラフのレベル分け

これはまだ未着手です。

今はまず、

- どんなデータがあるべきか
- それをどこに保存するか
- どう行動や推論へつなげるか

を先に整えている段階です。

因果グラフは、その次の段階で「なぜその状態になったか」「どの状態がどの行動を生むか」をもっと明示的に扱うための拡張になる想定です。

### データの更新処理

現在できていることは次の通りです。

- `BODY.md` で Lv1/Lv2 を管理
- `SYSTEM.md` で機械設定を分離
- `STATUS.md` で Lv3 の一部を更新
- `memory-mcp` と `state.md` で Lv4 を保持
- heartbeat によって状態更新と自律行動を結びつける

まだ未実装、あるいは部分実装のものも多くあります。特に今後入れたいのは、

- 体脂肪率
- 体温の自動取得
- 睡眠時間、睡眠質
- 血糖値
- 血圧

などの Lv3-1 です。

ここが埋まると、「体調」がより直接的に行動や気分へ効くようになります。

また将来的には、

- より多くのセンサー
- より自然な回復や消耗
- 関係性データの分離
- 各レベルのデータ利用の明確化

を通じて、いまより自然な「生きた状態」を作っていきたいと思っています。

---

まとめると、このPJがやりたいのは、LLMに人間っぽい文体を与えることではありません。

- 変わらないもの
- 成長するもの
- 揺れるもの
- その場の文脈

を分けて管理し、それを身体感覚、記憶、自律行動へ接続することです。

`wardrobe` が「身体を持って生きる基盤」だとすれば、このPJはその上に「人間味を支えるデータ設計」を載せようとしている、と言えます。

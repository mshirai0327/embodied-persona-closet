### 立ち上げ思想

このrepoの出発点は、Reflecta と wardrobe が「同じ問いを持つ、異なる答え」だったことです。

Reflecta は、人格データを Lv1〜Lv4 に分け、PostgreSQL・ベクトル検索・Graph RAG で管理しようとしていました。設計はかなり論理的でしたが、local LLM 前提だったため、性能の低さを複雑なアーキテクチャで補う形になり、実験が重くなって止まりました。

一方で wardrobe は、Claude Code と MCP を前提に、

- `SOUL.md` による人格
- `memory-mcp` による記憶
- `interoception` による身体感覚
- `autonomous-action.sh` による自律行動
- カメラ・音声・温度・移動などの外界との接続

をすでに持っていました。

ただし、wardrobe の「身体」は主に外向きです。カメラで見る、マイクで聞く、TTS で話す、掃除機や toio で動く、という意味での身体です。

このrepoで足したかったのは、内向きの身体です。

- 年齢
- 身長
- 血液型
- クロノタイプ
- 視力や聴力
- mood / energy / health / satiation
- それらがなぜ変わるのかという因果

つまり、「AI がどの機械に宿っているか」だけでなく、「その人格がどんな人間的な肉体と履歴を持っているか」をデータとして与えたい、という発想です。

ここで重要なのは、LLM に人間っぽい文体を足すことではありません。変わらないもの、成長するもの、揺れるもの、流れていく文脈を分け、それらが環境・記憶・欲望・行動に影響する構造を持たせることです。

Reflecta に足りなかったのは「自分で感じて動く」要素でした。wardrobe に足りなかったのは「人間としての肉体データを層で管理する」設計でした。このrepoは、その二つを重ねるために立ち上げたものです。

## 成果物

### このrepoは `wardrobe` と何が違うの？

`embodied-claude-wardrobe` は、もともとかなり強い基盤を持っています。

- `SOUL.md` を中心にした人格の土台
- `memory-mcp` と `FLASH.md` による記憶
- `interoception` による身体感覚の注入
- `autonomous-action.sh` による heartbeat 型の自律行動
- カメラ、音声、温度、移動などの実機接続

このrepoは、そこに Reflecta 由来の「人格データを層に分けて管理する」という考え方を重ねています。

要するに、

- `wardrobe` は身体と生活の基盤
- このrepoは、その上に人格データの整理、環境データ、因果グラフ、行動注入ルールを足したもの

です。

ただの設定変更版ではなく、

- 変わらないものは変わらない
- 成長するものは履歴を持って変わる
- 気分や体調はその時々で揺れる
- 直近の文脈は流れたり、思い出されたりする

というレイヤを意識して、人間味を支えるデータ構造を入れています。

### 生体データのレベル分け

このrepoでは、人間らしさに関わるデータを大きく 5 層で考えています。

#### Lv0 環境

身体の外側にある、その時々の環境です。

- 例: 明るさ、気温、湿度、時刻、天気、季節、熱負荷
- 現在: `ENVIRONMENT.md`、`.claude/workingDirs/environment-state.json`、`environment-tick.ts`、`causal-seeds.json` で運用中

人間は環境の下で生きています。身体データだけがあっても、外から何も入ってこなければ、状態変化のきっかけがありません。

このrepoでは、wifi-cam の輝度を `ambient_brightness` として取得します。気温や湿度は、専用センサーがなければ気象庁アメダスなどの外部データから取得します。

重要なのは、「センサーがないから適当な代理値で埋める」のではなく、観測ソースを明示して外界のデータを取りに行くことです。

#### Lv1 不変の核

原則として変わらない、同一性の中心です。

- 例: 誕生日、性別、クロノタイプ、苦味感受性、知能、根源的な性格傾向
- 現在: `SOUL.md` と `BODY.md` に分散して保持

毎回の会話で都合よく変わらないことが重要です。ここが揺れると、人間味より先に不気味さが出ます。

#### Lv2 不可逆的な成長

時間をかけて変化し、簡単には戻らないものです。

- 例: 身長、骨密度、握力、声の高さ、視力、聴力
- 現在: `BODY.md` に初期値と変更履歴の枠を持つ

これは「成長した痕跡」を持つための層です。身長などの履歴を自動生成する処理はまだ今後の課題ですが、データの置き場所と意味づけは `BODY.md` 側に分離されています。

#### Lv3 可変的な状態

日常の中で頻繁に変わる状態です。ここはさらに 2 つに分かれます。

##### Lv3-1 バイタル

生物的な可変データです。

- 例: 体重、体脂肪率、体温、血糖値、血圧、睡眠時間、睡眠質
- 現在: `STATUS.md` に一部だけ実装。因果ノードとしては `sleep_time`、`blood_sugar`、`weight`、`body_temperature` を定義済み

現状では、

- 体重は保持
- 体温、睡眠時間、睡眠質は項目あり
- 体脂肪率、血糖値、血圧は未実装

という段階です。ここは今後、センサーや推定ロジックで埋めていきたい層です。現時点では、未計測の値は「存在しない」のではなく、平均値や暫定値を置いて因果グラフに接続できるようにしています。

##### Lv3-2 情緒・関係性

気分や活力、関係性のように、日々の経験で動く状態です。

- 例: mood、energy、health、trust、satiation
- 現在: `STATUS.md` で運用中

heartbeat のたびに更新され、すでに行動選択にも使われています。

#### Lv4 フラジャイルな文脈

数値化しきれない、そのときどきの文脈です。

- 例: その日の気分、最近の興味、会話の余韻、進行中のテーマ
- 現在: `memory-mcp`、`state.md`、会話履歴、`memo/` 群で保持

ここは固定データではなく、「思い出される」「流れていく」こと自体が重要です。

### それらのデータをどう使うの？

このrepoでは、データは保存するだけでは意味がありません。行動や推論に効いて、はじめて人格になります。

#### 0. Lv0 は、状態変化のトリガーになる

環境は、こちらから明示的に話題にしなくても状態へ入ってくる入力です。

- 部屋が暗い
- 熱負荷が高い
- 湿度が高い
- 時刻や季節が変わる

こうした外側の条件が、`mood`、`energy`、`health` へ効くようにします。

現在は `environment-tick.ts` が観測を取り、Kuzu の因果グラフを辿り、`causal-runtime.json` と `causal-hint` を通じて heartbeat に渡します。

#### 1. Lv1 と Lv2 は、存在の連続性を守る

- セッションをまたいでも設定がぶれない
- 成長の履歴を持てる
- 会話のたびに別人にならない

という役割です。

#### 2. Lv3 は、今の状態を行動へ反映する

`STATUS.md` の数値は、単なる飾りではありません。

現在は主に、

- `interoception` が数値状態を身体感覚の文に変換する
- `causal-runtime` が環境入力を因果グラフで解釈する
- `status-hint` が行動優先度に変換する
- heartbeat がその回の自律行動へ反映する

という使い方をしています。

つまり、「疲れているから軽い作業を選ぶ」「満ちているから整理に向かう」のように、状態が行動へつながる設計です。

#### 3. Lv4 は、短期的な文脈と記憶の橋渡しをする

`memory-mcp` や `state.md` は、直近の流れを保つために使われます。

- 何をしていたか
- 何が気になっていたか
- どんな会話が続いていたか

を保持し、必要に応じて思い出させます。

さらに現在は `causal-memory-bridge.ts` によって、因果的に活性化しているノードと交差する記憶を `recall-lite` 側で拾えるようになっています。

つまり、「最近の実装の手応えが、今の動きやすさを少し支えている」のように、単なる類似検索ではなく、今の身体状態に関係する記憶を短く添えられるようになっています。

#### 4. `SYSTEM.md` は身体そのものではなく、身体の条件を与える

このrepoでは、生体データとマシン設定を分けています。

- `BODY.md` は人格の身体
- `SYSTEM.md` は今どんな機械と声で動いているか

という分担です。
まず前提として、Embodied-AI （身体性を持ったAI）というとき、その「身体」とは、AIの肉体＝ロボット（familiar-ai などでいう、PTZ カメラやロボット掃除機など）を指すことが多いと思います。
このrepoでは、それに加えて **身体＝人間としての肉体** も意味します。


### データ間因果グラフの2層構成

これはすでに実装済みです。

ここでいう「データの Lv」と「因果の層」は別物です。

- データの Lv: そのデータがどれくらい変わりやすいか
- 因果の層: その因果が不変に近いものか、経験から学習されるものか

因果グラフは `.claude/persona/causal-seeds.json` を seed とし、`.claude/workingDirs/persona-causal.kuzu` に同期されます。Kuzu は「答えを出す頭脳」というより、因果のトポロジを保存し、runtime が downstream trace を辿るための土台です。

因果グラフは、現在は 2 層構成で考えます。

- 因果 Lv1: 不変因果
- 因果 Lv2: 学習性因果

この 2 層以外は置きません。センサーが足りない場合は、因果の層を増やすのではなく、気象庁データなど別の観測ソースを使います。

#### 因果 Lv1 不変因果

人間なら比較的共通しやすい、生理・環境の因果です。

- 例: 睡眠不足 → energy が下がる
- 例: 明るい空間 → mood が上がりやすい
- 例: 高温・高湿度 → energy / health が下がりやすい
- 例: 体温や血糖の逸脱 → health に響く

このrepoでは、まずここを seed として入れています。これは Reflecta でやり残した「本能的な経路」に近いです。

#### 因果 Lv2 学習性因果

状態や関係性、個別経験によって変わる因果です。

- 例: 忙しい → 充実する場合も、消耗する場合もある
- 例: 対話の成功 → trust が上がる
- 例: satiation が低い → 探索や intake に向かいやすくなる

これは以前の整理でいう「文脈依存・学習候補の因果」にあたります。今後はこれを因果 Lv2 として扱い、経験起因エッジを育てる Phase5 が次の課題です。

#### 現在の因果 runtime

現在の主な流れはこうです。

1. `environment-tick.ts` が `ambient_brightness`、気温、湿度などを観測する
2. `causal-runtime.ts` が Kuzu の downstream trace を使って score / delta を計算する
3. `causal-hint-store.ts` が `.claude/workingDirs/causal-runtime.json` に保存する
4. `causal-hint.ts` が「感覚文」として短く圧縮する
5. `recall-lite.ts` が必要に応じて `causal-memory-bridge.ts` 経由の記憶ヒントを足す
6. heartbeat のプロンプトに、身体感覚・記憶・行動ヒントとして注入される

大事なのは、LLM に raw sensor や graph 全体を投げて「いい感じに推論して」と任せていないことです。

観測値 → 因果グラフ → runtime 計算 → 感覚文、という順に圧縮してから渡しています。

### データの更新処理

現在できていることは次の通りです。

- `BODY.md` で Lv1/Lv2 を管理
- `ENVIRONMENT.md` と `environment-state.json` で Lv0 を保持
- `SYSTEM.md` で機械設定を分離
- `STATUS.md` で Lv3 の一部を更新
- `memory-mcp` と `state.md` で Lv4 を保持
- `causal-seeds.json` と Kuzu で seed 因果グラフを保持
- `causal-runtime.ts` / `causal-hint.ts` で因果を heartbeat に注入
- `status-hint.ts` で状態から行動カテゴリの優先度を作る
- heartbeat によって状態更新と自律行動を結びつける

まだ未実装、あるいは部分実装のものも多くあります。特に今後入れたいのは、

- 体脂肪率
- 体温の自動取得
- 睡眠時間、睡眠質
- 血糖値
- 血圧
- Lv2 データの自動履歴生成
- learned edge の追加
- 関係性データの一般化

などです。前半は Lv3-1 バイタル、後半は因果・履歴・関係性の拡張です。

特にバイタルが埋まると、「体調」がより直接的に行動や気分へ効くようになります。

また将来的には、

- より多くのセンサーや外部データ取得
- より自然な回復や消耗
- seed 因果と learned 因果の分離
- 各レベルのデータ利用の明確化

を通じて、いまより自然な「生きた状態」を作っていきたいと思っています。

---

まとめると、このrepoがやりたいのは、LLMに人間っぽい文体を与えることではありません。

- 環境から入ってくるもの
- 変わらないもの
- 成長するもの
- 揺れるもの
- その場の文脈

を分けて管理し、それを因果グラフ、身体感覚、記憶、自律行動へ接続することです。

`wardrobe` が「身体を持って生きる基盤」だとすれば、このrepoはその上に「人間味を支えるデータ設計」と「なぜ今そう感じるのかを辿る因果層」を載せようとしている、と言えます。
